# Consolidated Review Evidence

Status: Phase 3 slice 3 adversarial-verification map

Date: 2026-07-25

This is the criterion-to-test index for the implemented slices described by
`docs/phase1-implementation.md`, `docs/phase2-scope-proposal.md`, and ADRs
0002 through 0006. Test names below are exact. The feature command starts from
an empty PostgreSQL 16 database, applies migrations `0001` through `0008`,
loads deterministic seed data, and runs separate non-owner API and worker
roles.

Status meanings:

- **Automated adversarial**: the test attempts a forbidden action or corrupt
  input and asserts rejection, isolation, non-invocation, or tamper detection.
- **Automated positive**: an executable test proves the expected successful
  path.
- **Automated command**: a repository command is the acceptance proof.
- **Manual**: deliberately requires human inspection; it is not represented as
  automated coverage.
- **GAP**: no dedicated automated or defined manual proof currently exists.

## GAP summary

One criterion remains explicitly uncovered by a dedicated automated negative-path
test:

1. **Malformed execution-provider output:** execution output is schema-validated
   in code, but no feature test currently injects malformed execution-provider
   output and proves that no result is persisted.

These are evidence gaps, not claims that the underlying enforcement is absent.
They are not among the eight mandatory standing-guarantee sweep items. No GAP
is silently represented as automated coverage.

## Manual evidence

- Production Google Workspace OIDC requires a configured provider and is not
  exercised by the deterministic local feature suite.
- CSV upload/result browser interaction is compiled and smoke-tested but does
  not have browser automation.

## Integrity boundaries and explicit deferrals

- The audit chain detects partial database-history tampering. It is not an
  external cryptographic anchor against a privileged administrator who rewrites
  and re-hashes the entire stream.
- Seven-day expiry makes a later duplicate a new intent; semantic duplicate
  detection is not implied.
- Gmail `drafts.create` has an ambiguous provider-accepted/database-not-stored
  crash window because Google accepts no client idempotency key. Network
  enablement remains prohibited until that policy is approved.
- Administrative dead-letter replay, N-approver collection, approval
  cancel/expiry, Gmail send, other connector mutations, scheduled connector
  ingestion, and batch compensation remain deferred under their existing ADR
  triggers.
