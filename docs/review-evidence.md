# Consolidated Review Evidence

Status: Supervised Gmail draft live-pilot tooling closeout map

Date: 2026-07-25

This is the criterion-to-test index for the implemented slices described by
`docs/phase1-implementation.md`, `docs/phase2-scope-proposal.md`, and ADRs
0002 through 0007. Test names below are exact. The feature command starts from
an empty PostgreSQL 16 database, applies migrations `0001` through `0009`,
loads deterministic seed data, and runs separate non-owner API and worker
roles.

Status meanings:

- **Automated adversarial**: the test attempts a forbidden action or corrupt
  input and asserts rejection, isolation, non-invocation, or tamper detection.
- **Automated positive**: an executable test proves the expected successful
  path.
- **Automated command**: a repository command is the acceptance proof.
- **Manual**: deliberately requires human inspection; it is not represented as
  automated coverage.
- **GAP**: no dedicated automated or defined manual proof currently exists.

## Provider-output boundary inventory

The repository has three provider calls whose returned data can drive durable
state. No other provider-output boundary was found by tracing production calls
to `generateStructured()` and `execute()`.

| Boundary                    | Runtime validation before provider-derived persistence                                                                                                                                                                                                                                    | Adversarial feature proof                                                                                                                                                                                                                                      |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Classification model output | `ClassificationAgent.run()` parses the untrusted value with `classificationOutputSchema` before the worker can insert an agent run, mutate classified task fields, transition to `classified`, append `task.classified`, or enqueue recommendation work.                                  | `apps/api/src/vertical-slice.integration.test.ts` — `rejects malformed classification output before provider-derived persistence`                                                                                                                              |
| Recommendation model output | `RecommendationAgent.run()` parses the untrusted value with `recommendationOutputSchema` before policy evaluation, recommendation/approval inserts, workflow transition, or recommendation/policy audit.                                                                                  | `apps/api/src/vertical-slice.integration.test.ts` — `rejects malformed recommendation output before provider-derived persistence`                                                                                                                              |
| Execution provider output   | `processInternalExecutionJob()` parses the untrusted value with `executionProviderOutputSchema`; Gmail commands also require `gmailDraftProviderOutputSchema` and the authorized payload hash. Only then can a provider result, success audit, or terminal success transition be written. | `apps/api/src/vertical-slice.integration.test.ts` — `rejects malformed execution output before provider-derived persistence`; `apps/api/src/gmail-draft.integration.test.ts` — `rejects common-valid but Gmail-invalid provider output before materialization` |

Execution deliberately records `execution.started` and enters `executing`
before invoking a provider. Those are attempt-lifecycle facts, not facts
derived from provider output. A malformed response cannot write an execution
result, success audit, or terminal transition. Its retry error is visible; on
bounded exhaustion the system writes a sanitized internal failure result,
transitions to `execution_failed`, and dead-letters the command. The malformed
payload itself is never persisted.

## GAP summary

No automated review-evidence gap remains for the operator tooling.
Classification, recommendation, common execution, Gmail-specific execution,
and the live-pilot enable/preflight/disable controls each have an adversarial
feature proof against clean PostgreSQL 16. The one real draft is intentionally
a pending manual proof, not an automated gap or a CI action.

## Manual evidence

- Production Google Workspace OIDC requires a configured provider and is not
  exercised by the deterministic local feature suite.
- CSV upload/result browser interaction is compiled and smoke-tested but does
  not have browser automation.
- The first real Gmail draft, mailbox inspection, replay observation,
  credential teardown, secret-containment review, and manual draft discard use
  the supervised runbook and blank evidence template. No live call occurs in
  CI.

## Integrity boundaries and explicit deferrals

- The audit chain detects partial database-history tampering. It is not an
  external cryptographic anchor against a privileged administrator who rewrites
  and re-hashes the entire stream.
- Seven-day expiry makes a later duplicate a new intent; semantic duplicate
  detection is not implied.
- Gmail `drafts.create` has an ambiguous provider-accepted/database-not-stored
  crash window because Google accepts no client idempotency key. Network
  enablement remains prohibited until that policy is approved.
- Administrative dead-letter replay, N-approver collection, approval
  cancel/expiry, Gmail send, other connector mutations, scheduled connector
  ingestion, and batch compensation remain deferred under their existing ADR
  triggers.
